# 날씨 · 블로그 언급순 · 장소 상세 설정 가이드

길찾기 키(TMAP·ODsay)는 [route-api-keys.md](route-api-keys.md)를 보세요.
이 문서의 키는 모두 **데이터 수집(GitHub Actions)에서만** 쓰이며 브라우저로 나가지 않습니다.

| 기능 | 필요한 것 | GitHub Secret |
|---|---|---|
| 🌤️ 지역 날씨 (3일 예보) | 공공데이터포털 **기상청 단기예보** 활용신청 | 추가 Secret 불필요 (`TOUR_API_KEY` 재사용) |
| ✍️ 블로그 언급순 정렬 | 네이버 개발자센터 **검색 API** | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` |
| 📖 장소 상세 (운영시간·사진 등) | 없음 (TourAPI 키 그대로) | — |
| 🎉 축제·행사 | 없음 (TourAPI 키 그대로) | — |
| 🧭 지역 추천 코스 | 없음 (TourAPI 키 그대로) | — |

## 1. 날씨 — 기상청 단기예보

공공데이터포털 인증키는 **계정당 하나**라서, 서비스를 활용신청만 하면 지금의 `TOUR_API_KEY`로 동작합니다.

1. [공공데이터포털](https://www.data.go.kr)에서 **기상청_단기예보 ((구)_동네예보) 조회서비스** 검색
2. **활용신청** → 목적 입력 후 신청 (보통 자동 승인)
3. 승인 후 키가 동작하기까지 **최대 1~2시간** 걸릴 수 있습니다
4. 끝. 다음 배포부터 지역 이름 아래에 오늘·내일·모레 날씨가 나옵니다

- 250개 시·군·구마다 하루 1회(총 250회) 호출합니다. 개발계정 한도(일 10,000회) 안입니다.
- 다른 키를 쓰고 싶으면 `KMA_API_KEY` Secret을 따로 등록하면 그 키를 우선 사용합니다.
- 수집은 매일 새벽 3시 배포 때 이루어지므로, 예보는 그 시각 발표 기준입니다.

로컬에서 확인:

```bash
npm run data:fetch   # 로그에 "기상청 날씨: 250/250개 지역"이 나오면 성공
```

## 2. 블로그 언급순 — 네이버 검색 API

네이버 플레이스의 리뷰·별점은 공식 API가 없고 크롤링은 이용약관 위반입니다.
대신 공식 **블로그 검색 API**로 `"서귀포 섭지코지"`처럼 검색했을 때의 **블로그 글 수**를 인기 지표로 씁니다.

### 키 발급

1. [네이버 개발자센터](https://developers.naver.com) 로그인 → **Application > 애플리케이션 등록**
2. 애플리케이션 이름: 예) `korea-travel-map`
3. **사용 API**: `검색` 선택
4. **환경 추가**: `WEB 설정` → 웹 서비스 URL에 `https://sanguk57.github.io` 입력
   (서버에서 호출하므로 실제로는 검사되지 않지만 등록 양식상 필요합니다)
5. 등록 후 **Client ID**와 **Client Secret** 복사

### 넣기

```bash
# 로컬 .env.local
NAVER_CLIENT_ID=발급받은_ID
NAVER_CLIENT_SECRET=발급받은_Secret
```

GitHub: **Settings > Secrets and variables > Actions**에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` 등록.

### 동작 방식

- 검색 API 한도는 **하루 25,000회**입니다. 장소가 4만 곳이 넘어 하루에 다 못 받으므로
  **추천순 상위 장소부터 하루 20,000곳씩** 받고, 다음 날 이어서 받습니다 (약 2~3일이면 전체 수집).
- 한 번 받은 값은 14일 뒤 다시 갱신합니다.
- 수집된 곳이 생기면 정렬에 **블로그 언급순** 칩이 자동으로 나타납니다. 아직 못 받은 곳은 목록 뒤로 갑니다.
- 블로그 글 수는 장소 이름이 흔할수록 부풀려질 수 있는 **참고용 지표**입니다.

## 3. 장소 상세 — 운영시간·쉬는 날·주차·사진

추가 키는 필요 없습니다. TourAPI `detailCommon2`·`detailIntro2`·`detailImage2`를 장소마다 3번 호출합니다.

- TourAPI 개발계정은 기능별 **일 1,000회** 한도라 **하루 950곳씩** 쌓습니다.
  "모든 지역의 1위 → 2위 → …" 순서(같은 순위에서는 축제 → 관광지 → 음식점 → 숙소)라 전국에 고루 퍼집니다.
  2만 8천여 곳 전체는 약 한 달이 걸리고, 각 지역 인기 장소는 며칠 안에 채워집니다.
- 아직 수집되지 않은 장소는 **대한민국 구석구석** 검색 링크를 대신 보여줍니다.
- 공공데이터포털에서 TourAPI **운영계정**을 신청하면 한도가 늘어납니다. 승인되면 저장소
  **Settings > Secrets and variables > Actions > Variables**에 `DETAIL_DAILY_PLACES`(예: `5000`)를 추가하세요.
- 한 번 받은 상세는 60일(축제는 7일) 뒤 갱신합니다.
- 아직 수집 안 된 장소를 누르면 "상세 정보는 아직 준비 중이에요"가 표시됩니다.

## 4. 지역 추천 코스

- **관광공사 추천**: TourAPI 여행코스(1,000여 개)의 들르는 곳 목록(`detailInfo2`)을 하루 900개씩 받습니다.
  들르는 곳의 위치로 지역을 판단해, 들르는 곳이 있는 모든 지역에 표시합니다. 30일마다 갱신합니다.
- **자동 추천**: 키·호출 없이 브라우저에서 만듭니다. 지역 인기 관광지 3곳(가장 인기 있는 곳 반경 20km)
  \+ 근처 맛집 1곳 + 진행 중 축제가 가까우면 1곳을 묶고 동선을 최적화합니다.
- 코스에서 **내 코스로 담기**를 누르면 찜 목록에 들어가 실제 이동 시간을 계산합니다.

## 5. 맛집 상세 · 사진 채우기

- **네이버 지도홈 / 카카오맵 상세**: 장소를 누르면 두 버튼이 나옵니다. 네이버는 `지역 + 장소 이름`으로 지도를 검색하는 링크라
  결과가 하나면 그 장소의 지도홈(리뷰·메뉴·영업시간)이 바로 열리고, 여러 개면 검색 결과 목록이 열립니다.
  (네이버 검색 API는 장소 ID를 주지 않아 지도홈 주소를 직접 만들 수 없습니다)
- **사진 채우기**: 사진이 없는 장소(카카오 맛집 전체, 관광공사 일부)는 **카카오 이미지 검색**(기존 `KAKAO_REST_KEY`)으로
  블로그 사진 썸네일 3장을 받아 채웁니다. 맛집부터, 지역마다 고르게 하루 최대 10,000곳(정기 실행 20분, push 배포 3분).
  90일마다 갱신합니다.
- 웹 검색 사진이라 실제와 다를 수 있어 상세 화면에 출처 글 링크와 안내 문구를 함께 보여줍니다.

## 누적 데이터는 어디에 저장되나

장소 상세 파일(`public/data/details/`)과 수집 진행 상황(`.cache/enrich/state.json`)은 저장소에 커밋하지 않고
**GitHub Actions 캐시**로 다음 실행에 넘깁니다.

- 캐시는 7일간 쓰이지 않으면 GitHub가 지웁니다. 매일 배포가 돌기 때문에 보통 유지됩니다.
- 캐시가 지워지면 처음부터 다시 쌓기 시작할 뿐, 사이트가 깨지지는 않습니다.

로컬에서는:

```bash
npm run data:fetch    # 장소·축제·날씨 (매번 새로)
npm run data:enrich   # 상세·블로그 언급 수 (이어서 누적)
```
